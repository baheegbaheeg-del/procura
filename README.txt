SILAH PRO v1.1 — صِلَة
========================

تمت مراجعة النسخة الأصلية وإصلاح دورة العمل داخل التطبيق.

ما تم إصلاحه وربطه:
- إصلاح زر «نشر الطلب» وإظهار سبب أي نقص داخل النافذة نفسها.
- التحقق من اسم الشركة، المشروع، موعد العروض، مكان التوريد، الصنف، الكمية والوحدة.
- ترقيم طلبات الشراء تلقائيًا RFQ.
- حفظ وعرض المرفقات محليًا (حتى 1.5MB لكل ملف في هذه النسخة).
- شاشة تفاصيل طلب الشراء والبنود والمرفقات.
- المورد يرى الطلبات المفتوحة ويقدم عرضًا تفصيليًا لكل بند.
- منع تكرار عرض المورد لنفس الطلب: العرض السابق يتم تحديثه.
- حفظ شروط الدفع ومدة التوريد والتوفر والماركة والأسعار والخصم والنقل والضرائب والرسوم.
- العميل يرى فقط العروض المرتبطة بطلباته.
- المقارنة بندًا بندًا واختيار أقل عرض صالح لكل بند.
- تقسيم الطلب على أكثر من مورد.
- إنشاء أوامر شراء مرتبطة بالطلب والعميل والمورد والبنود.
- احتساب نصيب الخصم والنقل والضرائب والرسوم عند تقسيم الطلب.
- العميل يرى أوامر شرائه فقط، والمورد يرى أوامر توريده فقط، والإدارة ترى الكل.
- شاشة تفاصيل أمر الشراء.
- سجل نشاط مترابط.
- نسخ احتياطي JSON + استرجاع نسخة احتياطية.
- إنشاء ملف تعريف تلقائي لكل حساب يدخل التطبيق.

طريقة التجربة التشغيلية الآن:
1) افتح الموقع وسجل كـ «عميل / مشتريات» وأنشئ طلبًا.
2) اخرج وسجل ببريد آخر كـ «مورد»؛ سترى الطلب وتستطيع تقديم عرض.
3) اخرج وارجع بحساب العميل؛ ستجد العرض ويمكنك المقارنة وإصدار أمر الشراء.
4) ارجع لحساب المورد؛ سيظهر أمر التوريد.
5) حساب «إدارة صِلَة» يرى البيانات الإجمالية.

مهم جدًا — التشغيل الحقيقي بين أجهزة مختلفة:
هذه الحزمة ما زالت تستخدم Local Storage لأنها نفس بنية المشروع الأصلي. لذلك الربط يعمل فورًا بين الأدوار على نفس المتصفح/الجهاز، لكنه ليس قاعدة بيانات مشتركة بين أجهزة مختلفة.
لكي تصبح منصة إنتاج فعلية لعملاء وموردين على أجهزة متعددة يلزم ربط Backend/Database سحابية وتسجيل دخول حقيقي وتخزين ملفات سحابي. لا يصح اعتبار Local Storage بديلاً عن ذلك.

الرفع على Vercel:
الحزمة Static ولا تحتاج Build command. ارفع المجلد كما هو أو اربطه بمستودع GitHub ثم Deploy على Vercel.
